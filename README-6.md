# 과제 13: 병합 정렬과 퀵 정렬의 성능 비교

## 1. 파일 구성

| 파일 | 설명 |
|---|---|
| `merge_vs_quick.c` | 병합 정렬, 퀵 정렬(First / Random / Median-of-Three) 구현 및 성능 측정 프로그램 |
| `result.txt` | 프로그램 실행 결과 원문 |
| `README.md` | 본 문서 |

컴파일 및 실행 방법:

```bash
gcc -O2 -Wall -o merge_vs_quick merge_vs_quick.c
./merge_vs_quick > result.txt
```

## 2. 실험 조건

- **데이터 생성:** `rand() % 100000`으로 무작위 정수를 생성합니다. 이전 과제(퀵 정렬 피벗 비교)와 동일한 방식입니다. 시드는 `srand(12345)`로 고정했으므로 다시 실행하면 같은 데이터가 생성됩니다.
- **데이터 크기:** n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000
- **중복 허용:** 값 범위가 0~99,999이므로 중복이 일부 존재할 수 있습니다.
- **동일 입력 보장:** 각 데이터 크기에서 원본 배열 하나를 만들고, 알고리즘마다 `memcpy`로 복사한 배열을 정렬합니다.
- **정렬 방향:** 오름차순입니다.
- **컴파일 옵션:** `gcc -O2`입니다.

## 3. 측정 방법

### 3.1 숫자 비교 횟수
- **병합 정렬:** `merge_range`의 `a[i] <= a[j]` 비교 한 번을 1회로 셉니다. 한쪽 배열이 먼저 소진된 뒤 남은 원소를 복사하는 과정은 비교가 없으므로 세지 않습니다.
- **퀵 정렬(Lomuto 분할):** 분할 과정에서 `a[j] < pivot` 비교 한 번을 1회로 셉니다.
- **Median-of-Three:** 첫 원소, 가운데 원소, 마지막 원소의 중앙값을 찾는 데 쓴 값 비교(2~3회)를 분할 비교에 더해서 셉니다.
- **제외 항목:** 반복문의 인덱스 및 종료 조건 검사, 무작위 위치 생성, 원소 교환(데이터 이동)은 세지 않습니다.

### 3.2 실행 시간
- `clock()`으로 정렬 함수 호출 전후 시간을 재고, 그 차이를 ms 단위로 환산합니다.
- 배열 복사와 데이터 생성 시간은 측정에서 제외합니다.
- 각 알고리즘을 같은 데이터로 20회 반복 실행하고 평균을 기록합니다. 한 번 실행하면 시간이 너무 짧아 측정 오차가 크기 때문입니다.
- 무작위 피벗의 난수 상태는 실행마다 같은 값으로 초기화하므로, 20회 실행의 비교 횟수는 모두 같습니다.

### 3.3 메모리 사용량 (계산 기준)
원본 데이터 배열은 공통 비용이므로 제외하고, 정렬 과정에서 추가로 필요한 메모리만 **계산으로 추정**했습니다. 프로파일러 대신 계산식을 쓴 이유는 재귀 호출 깊이와 할당 크기를 정확히 알 수 있기 때문입니다.

| 알고리즘 | 계산식 |
|---|---|
| 병합 정렬 | 임시 배열 `n × sizeof(int)` + 최대 재귀 깊이 × 프레임 크기 |
| 퀵 정렬 (3종 공통) | 최대 재귀 깊이 × 프레임 크기 (보조 배열 없음) |

- **프레임 크기:** 병합 정렬은 `2 × sizeof(int*) + 3 × sizeof(int)` = 28 Byte, 퀵 정렬은 `sizeof(int*) + 3 × sizeof(int)` = 20 Byte로 두었습니다. 함수 인자(배열 포인터, 시작·끝 인덱스)와 지역 변수(중간 인덱스, 피벗 위치)를 기준으로 한 추정치입니다.
- **최대 재귀 깊이:** 실제 정렬 중 재귀 호출 깊이를 `cur_depth`로 추적해서 최댓값을 사용했습니다.
- 이 값은 실제 할당기나 컴파일러가 만드는 스택 프레임 크기와 다를 수 있으므로, 알고리즘 간 상대 비교용으로 보는 것이 적절합니다.

### 4.2 데이터 크기 증가에 따른 비교 횟수 변화
- **병합 정렬:** n이 2배 늘 때 비교 횟수는 약 2.1~2.2배로 증가합니다. 병합 정렬은 입력에 관계없이 약 n log n 번 비교하므로, 이 증가율은 n log n 곡선과 일치합니다. 20,000개에서 측정값 260,948은 n log₂n − n + 1 ≈ 265,000과 거의 같습니다.
- **퀵 정렬 3종:** 비교 횟수도 대체로 n log n 형태로 증가하지만, 병합 정렬보다 상수가 큽니다. 같은 n에서 퀵 정렬(First)은 병합 정렬보다 약 42% 더 많이 비교했습니다(20,000개: 369,711 vs 260,948).

### 4.3 실행시간 차이
- **모든 크기에서 병합 정렬이 가장 느렸습니다.** 20,000개에서 병합 정렬은 1.82ms, 퀵 정렬 3종은 1.28~1.31ms로 약 40% 차이가 났습니다.
- 병합 정렬이 비교 횟수는 적은데도 느린 이유는 다음과 같습니다.
  - 병합 과정에서 모든 원소를 임시 배열로 옮겼다가 다시 원본으로 복사합니다. 레벨마다 2n번 쓰기가 일어나므로 메모리 이동량이 많습니다.
  - 퀵 정렬은 분할 과정에서 교환(swap)이 대부분 원소를 제자리에서 옮깁니다. 캐시 지역성이 좋아서 같은 비교 횟수라도 빠르게 실행됩니다.
- 퀵 정렬 3종의 시간 차이는 0.1ms 안팎으로 작고, 측정 반복마다 흔들리는 폭과 비슷합니다. 따라서 세 퀵 정렬의 시간 순위는 의미 있는 차이로 보기 어렵습니다.

### 4.4 메모리 사용량 차이
- **병합 정렬은 n에 비례해서 메모리를 씁니다.** 임시 배열 `n × 4 Byte`가 주된 비용이므로 20,000개에서 약 80KB를 추가로 사용했습니다.
- **퀵 정렬은 재귀 깊이만큼만 씁니다.** 보조 배열이 없고 재귀 깊이가 대략 log n 수준이어서, 세 방식 모두 1KB 이하입니다.
- 병합 정렬은 퀵 정렬보다 약 120배 많은 메모리를 사용했습니다(20,000개: 80,420 vs 660 Byte). 이 차이는 **공간 복잡도 O(n) 대 O(log n)** 의 차이가 그대로 드러난 결과입니다.

### 4.5 퀵 정렬의 피벗 선택 방법에 따른 차이
- **Median-of-Three**가 세 방식 중 비교 횟수가 가장 적었습니다. 20,000개에서 323,027회로, First(369,711회)보다 약 12.6% 적었습니다. 세 값의 중앙값을 피벗으로 쓰면 피벗이 극단값에 걸릴 확률이 줄어 분할이 더 균형 잡히기 때문입니다.
- **Random**은 n이 커질수록 First보다 적은 비교 횟수를 보였습니다(20,000개: 345,679회). 무작위 피벗은 입력 순서에 따른 최악의 경우를 피하지만, 이 실험의 데이터는 이미 무작위이므로 First도 나쁜 상황에 빠지지 않았습니다. 따라서 이 실험에서는 무작위 피벗의 이득이 크게 드러나지 않았습니다.
- **First**는 이번 실험에서 비교 횟수가 가장 많았습니다. 입력이 무작위일 때는 성능 저하가 없지만, 이미 정렬된 입력이 들어오면 분할이 한쪽으로 치우쳐 O(n²)으로 악화됩니다. 이번 실험은 무작위 데이터만 사용했으므로 이 최악의 경우는 측정하지 않았습니다.
- 피벗 선택 방법에 따른 시간 차이는 작았습니다. Median-of-Three는 값 비교가 2~3회 추가로 필요하지만, 비교 횟수 감소가 이를 상쇄했습니다.

### 4.6 시간 복잡도와 공간 복잡도 비교

| 항목 | 병합 정렬 | 퀵 정렬 |
|---|---|---|
| 최선 시간 복잡도 | O(n log n) | O(n log n) |
| 평균 시간 복잡도 | O(n log n) | O(n log n) |
| 최악 시간 복잡도 | O(n log n) | O(n²) (First, Median-of-Three는 특정 입력에서) |
| 공간 복잡도 (추가) | O(n) (임시 배열) | O(log n) 평균 (재귀 스택) |
| 안정 정렬 여부 | 안정 | 불안정 |

- 병합 정렬은 최악의 경우에도 O(n log n)을 보장하지만, 추가 메모리 O(n)을 씁니다.
- 퀵 정렬은 추가 메모리가 적고 평균적으로 빠르지만, 최악의 경우 O(n²)이 될 수 있습니다. 이번 실험의 무작위 데이터에서는 이 최악의 경우가 나타나지 않았습니다.
- 이번 실험에서 비교 횟수는 퀵 정렬(Median-of-Three)이 가장 적었지만, 실행시간은 병합 정렬이 가장 길었습니다. 비교 횟수만으로 실행 시간을 설명할 수 없다는 점이 확인됩니다. 실행시간에는 메모리 이동과 캐시 효율이 큰 영향을 주기 때문입니다.

## 5. 결론
1. **비교 횟수:** 병합 정렬은 입력과 상관없이 n log n에 가깝게 비교하며, 퀵 정렬은 피벗 방식에 따라 비교 횟수가 달라집니다. 무작위 데이터에서는 Median-of-Three < Random < First 순으로 적었습니다.
2. **실행시간:** 이번 환경에서는 퀵 정렬이 병합 정렬보다 약 30~40% 빨랐습니다. 병합 정렬의 임시 배열 복사 비용이 원인입니다.
3. **메모리:** 병합 정렬은 O(n) 추가 메모리(20,000개 기준 약 80KB)가 필요하고, 퀵 정렬은 O(log n)(약 1KB 이하)입니다.
4. **한계:** 실행시간은 한 환경에서 20회 평균으로 측정했으므로 다른 환경에서는 결과가 달라질 수 있습니다. 메모리는 계산 기준 추정치입니다. 또한 무작위 데이터만 사용했기 때문에 퀵 정렬의 최악 경우(O(n²))는 확인하지 못했습니다.
