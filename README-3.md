# 정렬 알고리즘 성능·안정성 비교 실험 (C)

- 소스: `sort_exp.c` / 실행 결과 원문: `result.txt`
- 빌드·실행: `gcc -O2 -o sort_exp sort_exp.c && ./sort_exp` (난수 시드 고정 20240601)
- 데이터: `{key1, key2, ord}` 구조체 10,000개. key1·key2는 각각 0~1,000,000 독립 난수. `ord`는 원래 입력 순서(안정성 검증 전용, 정렬 기준 아님).
- 측정: 비교 = key1끼리 비교한 횟수(루프 조건 제외). 이동 = 구조체 전체의 대입 1회(교환=3, 삽입의 temp 저장·한 칸 이동·최종 삽입 각 1). 원본 복사·입력 준비는 제외.
- 구현: 선택(최솟값 위치가 다를 때만 교환), 버블(일반 / 조기 종료), 삽입(Case A `>`, Case B `>=`). 라이브러리 정렬은 알고리즘에 쓰지 않았고, `qsort`는 시험 입력(정렬·역순) 준비에만 사용(측정 제외).

## 1. 무작위 데이터 100회 (매 회 새 데이터 1개를 모든 알고리즘이 복사본으로 공유, 100회 모두 정렬 결과 검증 통과)

| 알고리즘 | 총 비교 | 평균 비교 | 평균 이동 |
|---|---|---|---|
| 선택 | 4,999,500,000 | 49,995,000 | 29,970.78 |
| 버블 | 4,999,500,000 | 49,995,000 | 74,994,665.31 |
| 버블(조기 종료) | 4,998,512,179 | 49,985,121.79 | 74,994,665.31 |
| 삽입(>) | 2,500,821,215 | 25,008,212.15 | 25,018,219.77 |
| 삽입(>=) | 2,500,826,221 | 25,008,262.21 | 25,018,269.84 |

**버블 일반 vs 조기 종료:** 평균 비교 차이는 약 9,878회(0.02%)에 불과하다. 무작위 데이터에서는 거의 마지막 패스까지 교환이 발생하므로 조기 종료가 거의 작동하지 않는다. 이동 횟수는 두 방식이 동일(교환 횟수 = 역전 쌍 수 ≈ n(n-1)/4 ≈ 2,500만, ×3).

## 3. 안정성 검증

**방법:** 각 데이터에 원래 순서 `ord`를 저장하고, 정렬 후 인접한 key1이 같은 쌍에서 `ord`가 감소하는 경우(순서 역전)를 센다. 0이면 안정.

**입력 데이터:** (a) 문제의 예시 4개 `(527,100)(527,200)(125,300)(892,400)`, (b) key1을 0~99로 제한해 키당 약 100개씩 중복되게 만든 10,000개 데이터.

| 알고리즘 | 예시 결과 | 중복 데이터 순서 역전 | 판정 |
|---|---|---|---|
| 선택 | (125,300)(527,**200**)(527,**100**)(892,400) | 3,245 | 불안정 |
| 버블 (조기 종료 포함) | (125,300)(527,100)(527,200)(892,400) | 0 | 안정 |
| 삽입 `>` | (125,300)(527,100)(527,200)(892,400) | 0 | 안정 |
| 삽입 `>=` | (125,300)(527,**200**)(527,**100**)(892,400) | 9,900 | 불안정 |

**원인**
- 선택 정렬: 멀리 떨어진 두 원소를 교환한다. 예시에서 index 0의 (527,100)이 최솟값 125와 자리 교환되어 (527,200) 뒤로 넘어갔다. 교환이 같은 키 원소를 뛰어넘기 때문에 불안정하다.
- 버블 정렬: 인접 원소를 `>`일 때만 교환하므로 같은 키는 서로 넘지 않는다. 안정.
- 삽입 정렬 `>` vs `>=`: `>`는 같은 키를 만나면 이동을 멈추고 그 뒤에 삽입하므로 기존 순서가 유지된다. `>=`는 같은 키도 밀어내고 그 앞에 삽입하므로 같은 키끼리 순서가 뒤집힌다(중복 테스트에서 9,900건 역전). 또한 `>=`는 같은 키를 더 많이 이동·비교하여 정렬된 입력에서도 비교 10,054/이동 20,053으로 `>`(9,999/19,998)보다 약간 많다(입력에 중복 키가 있기 때문).

## 4. 분석

1. **선택 정렬**: 입력 상태와 무관하게 비교가 항상 n(n-1)/2 = 49,995,000회다. 최솟값을 찾기 위해 남은 구간을 전부 훑기 때문이다. 이동은 교환 횟수(최대 n-1) × 3이라 가장 적다(무작위 약 3만, 정렬 입력 0, 부분 정렬 1,506). 이동 비용이 큰 데이터에 유리하지만 불안정하다.
2. **일반 버블 정렬**: 비교는 입력과 무관하게 항상 49,995,000회다. 이동은 교환 수(= 역전 쌍 수) × 3으로 입력에 크게 좌우된다. 무작위 약 7,500만, 역순 약 1.5억(최대), 정렬 0.
3. **조기 종료 버블**: 정렬 입력에서 한 패스(9,999회)만에 종료해 비교가 약 5,000분의 1로 줄었다. 부분 정렬에서는 약 0.5%만 감소(49,728,915), 무작위·역순에서는 효과가 거의 없거나 없다(역순은 마지막 패스까지 교환이 발생). 이동 횟수는 일반 버블과 동일하다. 즉 조기 종료는 비교 횟수만 줄이며, 거의 정렬된 입력에서도 큰 값이 앞쪽에 하나라도 있으면 패스 수가 줄지 않는다(작은 값은 패스당 한 칸씩만 앞으로 이동).
4. **삽입 정렬**: 비교·이동이 역전 쌍 수에 비례한다. 무작위에서는 약 n²/4(2,500만)로 선택·버블의 절반이고, 정렬 입력에서는 O(n) (비교 9,999), 부분 정렬에서는 약 315만으로 무작위의 1/8 수준이라 부분 정렬 데이터에서 가장 큰 이득을 본다. 역순에서는 최악(비교 49,995,000, 이동 약 5,001만)이지만 이동 수는 버블(약 1.5억)의 1/3이다. 이동 횟수에는 원소마다 temp 저장과 최종 삽입 2회가 고정으로 더해진다(정렬 입력의 19,998 = 2×9,999).
5. **종합**: 데이터가 정렬에 가까울수록 삽입 정렬(그리고 조기 종료 버블의 비교 횟수)이 극적으로 빨라지는 반면, 선택 정렬은 입력과 무관하게 비교 횟수가 일정하다. 이동 횟수 기준으로는 선택 < 삽입 < 버블 순이고, 안정성이 필요하면 버블이나 삽입(`>`)을 쓰고 선택과 삽입(`>=`)은 피해야 한다. 이 모든 차이는 역전 쌍의 수와 탐색 범위(항상 전체 vs 입력 의존)에서 비롯된다.
