# 과제 12: 퀵 정렬의 피벗 선택에 따른 성능 비교

## 1. 실행 방법

```bash
gcc -O2 -Wall -o quick_sort_pivot quick_sort_pivot.c
./quick_sort_pivot
```

## 2. 실험 설정

- 데이터: `rand() % 100000`으로 생성한 무작위 정수, 중복 허용
- 데이터 크기: n = 1000, 2000, 4000, 8000, 16000, 20000
- 세 방법은 같은 원본 데이터의 복사본을 사용
- 피벗 방법
  - First: 구간의 첫 번째 원소
  - Random: 분할할 때마다 무작위 위치 선택
  - Median-of-Three: 첫 번째, 가운데, 마지막 원소의 중앙값
- 비교 횟수: 분할 과정의 `원소 < 피벗` 비교와 Median-of-Three의 중앙값 결정 비교만 계산
- 결과 검증: 모든 정렬 결과가 오름차순인지 확인

## 3. 측정 결과 (10회 실행 평균)

| n | First | Random | Median-3 |
|---|---|---|---|
| 1000 | 11,000 | 11,035 | 10,844 |
| 2000 | 24,464 | 25,201 | 24,453 |
| 4000 | 53,223 | 52,907 | 53,108 |
| 8000 | 117,643 | 120,113 | 113,138 |
| 16000 | 266,692 | 263,699 | 252,382 |
| 20000 | 335,324 | 342,957 | 319,189 |

## 4. 분석

### 4.1 데이터 크기 증가에 따른 변화

세 방법 모두 n이 2배가 되면 비교 횟수가 약 2배보다 조금 더 늘어납니다. 퀵 정렬의 평균 시간 복잡도 O(n log n)과 일치하는 경향입니다. 비교 횟수는 n이 작을 때 방법별 차이가 거의 없고, n이 커질수록 Median-of-Three가 상대적으로 적어지는 경향을 보였습니다.

### 4.2 세 피벗 방법의 성능 차이

- **Median-of-Three**: 큰 n(8000 이상)에서 가장 적은 비교 횟수를 기록했습니다. n = 20000에서 약 319,000회로, First(약 335,000회)보다 약 5% 적었습니다.
- **First**: 입력이 무작위이므로 첫 원소도 사실상 무작위 값입니다. 따라서 Random과 비슷한 결과가 나왔습니다. 입력이 이미 정렬되어 있다면 First는 최악 상황(O(n²))에 빠지지만, 이번 실험은 무작위 데이터이므로 그 상황은 나타나지 않았습니다.
- **Random**: 입력 분포와 관계없이 최악 상황의 확률을 낮춥니다. 이번 실험에서는 First와 큰 차이가 없었고, 일부 크기에서는 오히려 많았습니다. 무작위 선택 자체가 비교 횟수를 줄이지는 않으므로 이는 자연스러운 변동입니다.

### 4.3 피벗 선택이 비교 횟수에 영향을 주는 이유

퀵 정렬의 비교 횟수는 피벗이 원소를 얼마나 고르게 둘로 나누는지에 따라 결정됩니다. 피벗이 중앙값에 가까우면 구간이 절반씩 나뉘어 재귀 깊이가 약 log n이 되고, 전체 비교 횟수는 약 n log n이 됩니다. 반대로 피벗이 최솟값이나 최댓값에 가까우면 한쪽 구간이 거의 비어 재귀 깊이가 n에 가까워지고 비교 횟수가 n²에 가까워집니다.

Median-of-Three는 세 값의 중앙값을 고르므로 극단적인 피벗이 선택될 확률을 낮춥니다. 이 때문에 분할이 더 균형 있게 이루어지고 비교 횟수가 줄어듭니다. 다만 중앙값을 찾기 위해 비교를 3회 추가로 하므로, 작은 n에서는 이 추가 비용이 이득보다 커서 오히려 비교 횟수가 늘어날 수 있습니다. 이번 결과에서 n = 1000에서는 Median-3가 가장 적었지만, 이는 10회 평균의 변동 범위 안의 차이이므로 확정적인 결론은 아닙니다.

### 4.4 결론

이번 실험에서 가장 효과적인 방법은 **Median-of-Three**였습니다. 특히 n이 큰 구간에서 비교 횟수가 가장 적었습니다. First와 Random은 무작위 데이터에서 거의 비슷한 성능을 보였습니다. 다만 차이는 대략 5% 이내로, 데이터가 정렬되어 있거나 특정 패턴을 가진 경우에는 결과가 크게 달라질 수 있습니다. 따라서 실제 구현에서는 입력 특성을 모를 때 Median-of-Three 또는 Random 방식이 더 안정적인 선택입니다.

## 5. [보너스] 재귀 vs 반복 퀵 정렬

조건: n = 10000, Median-of-Three, 10회 평균, 데이터 생성·배열 복사·결과 검증 시간 제외

| 구현 | 평균 실행 시간 |
|---|---|
| Recursive Quick Sort | 0.633 ms |
| Iterative Quick Sort | 0.649 ms |

### 분석

두 구현의 차이는 약 0.016 ms(약 2.5%)로 매우 작으며, 측정 노이즈 범위 안에 있습니다. 재귀 방식이 약간 빠른 결과를 보였습니다.

- **재귀 방식**: 함수 호출 스택을 컴파일러와 CPU가 최적화하기 쉽고, 호출 구조가 단순합니다.
- **반복 방식**: 명시적 스택을 배열로 직접 관리하므로 함수 호출 오버헤드가 줄어듭니다. 하지만 스택 push/pop 연산과 배열 접근이 추가되어 이득이 상쇄됩니다.

두 방식 모두 같은 분할 알고리즘과 같은 피벗 방식을 쓰므로 비교 횟수는 동일하며, 차이는 함수 호출 방식에서만 생깁니다. 재귀 깊이는 Median-of-Three 덕분에 대략 log n 수준이라 스택 오버플로 위험도 낮습니다. 이러한 이유로 n = 10000 규모에서는 두 방식의 실행 시간 차이가 거의 나타나지 않았습니다.

## 6. 참고 사항

- 실행 시간은 `clock()` 기반이므로 환경과 실행 시점에 따라 값이 달라집니다.
- 비교 횟수는 `rand()` 시드에 따라 실행마다 달라지므로, 위 표는 10회 평균값입니다.
